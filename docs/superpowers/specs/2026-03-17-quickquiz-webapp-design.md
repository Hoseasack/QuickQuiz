# QuickQuiz Web App — Design Spec
**Date:** 2026-03-17
**Status:** Approved

---

## Overview

A local Node/Express web app that accepts `.quiz` files via drag-and-drop or file picker and renders them as interactive quizzes. Supports multiple-choice, true/false, and multiple-select question types. Shows all questions at once, scores inline after submission, and shuffles questions and answers on retake.

---

## Architecture

```
QuickQuiz/
├── server.js              # Express server: static file serving + POST /api/quiz
├── src/
│   └── quiz-parser.js     # Existing parser: .quiz text → JSON (server-side only)
├── public/
│   ├── index.html         # Single-page UI
│   ├── app.js             # Client logic: file handling, rendering, scoring, shuffle
│   └── style.css          # Minimal styles
└── quizzes/
    └── example.quiz       # Committed example file
```

**Stack:** Node.js + Express, vanilla HTML/CSS/JS. No build step, no frontend framework.

---

## Data Flow

1. User drops or selects a `.quiz` file in the browser
2. Browser POSTs the raw file to `POST /api/quiz`
3. Express parses it with `quiz-parser.js`, returns JSON
4. `app.js` renders all questions at once
5. User answers all questions and clicks **Submit**
6. `app.js` scores inline and shows the score banner

The parser stays server-side. The browser only handles rendering and interaction.

---

## API

### `POST /api/quiz`
- **Request:** `Content-Type: text/plain` with raw `.quiz` file text as the body
- **Response 200:** `{ title, description, warning, questions: [{ id, type, text, answers: [{ text, correct }] }] }` (`warning` is `null` if absent)
- **Response 400:** `{ error: "<parser error message>" }`

---

## `.quiz` Format Extension

An optional `warning:` field in the preamble is now supported:

```
# Quiz Title
description: Optional description
warning: Answers were generated by Claude and may differ from the official key.
```

The parser surfaces this as a top-level `warning` string in the returned JSON, or `null` if the field is absent. Client code checks `if (data.warning)` to decide whether to render the banner.

## UI — Page Layout

| Region | Content |
|--------|---------|
| Top bar | Quiz title, description, question count |
| Warning banner | Yellow notice (only shown when `warning` field is present) |
| Question list | All questions, numbered, scrollable |
| Submit button | Fixed at bottom of list; disabled until all questions answered |
| Score banner | Appears at top after submit (e.g. "8 / 10 — Great job!") |

---

## Question Rendering

| Type | Identified by | Input control |
|------|--------------|---------------|
| Multiple choice | default (no tag) | Radio buttons |
| True / False | `[tf]` tag | Radio buttons: "True" / "False" |
| Multiple select | `[multi]` tag | Checkboxes |

---

## Inline Feedback (Post-Submit)

- All inputs locked immediately on submit
- Correct selections → green highlight
- Incorrect selections → red highlight + correct answer(s) shown beneath
- Unanswered / fully wrong questions → correct answer(s) revealed
- Score banner appears at top: `X / Y correct`

---

## Retake Behaviour

On clicking **Retake:**
- Questions are shuffled into a new random order
- Answer options within each question are also shuffled
- All inputs reset to unanswered state
- Score banner and feedback cleared
- Same quiz file — no re-upload required

---

## Error Handling

| Scenario | Behaviour |
|----------|-----------|
| Non-`.quiz` file dropped/picked | Inline error: "Please use a .quiz file" |
| Malformed `.quiz` file | Display parser error message verbatim |
| Empty quiz (no questions) | Caught by parser, shown as error |
| Submit with unanswered questions | Submit stays disabled; unanswered questions are continuously highlighted with a subtle border/colour as a visual guide — not triggered by a submit attempt |
| Server error | Generic inline error message |

---

## Constraints & Non-Goals

- **One quiz at a time** — no multi-file support
- **No persistence** — session only, no localStorage or database
- **No history** — no tracking of past scores or attempts
- **No timer** — untimed quizzes only
- **Local only** — runs on `localhost`, no auth, no deployment

---

## Success Criteria

- Drop or pick any valid `.quiz` file → quiz renders correctly
- All three question types render and score correctly
- Submit is blocked until all questions answered
- Inline feedback clearly distinguishes correct from incorrect
- Retake shuffles both questions and answers
- Invalid files produce clear, actionable error messages
- Warning banner appears when `warning:` field is present in `.quiz` preamble
